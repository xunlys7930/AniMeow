# 原版 SQLite v1–19 兼容矩阵

基准来自原版 `lib/db/database_helper.dart`。导入器不执行原版的逐级迁移 SQL，而是以只读方式枚举实际存在的表和列，再映射到原生 Room 模型，因此缺少后期字段不会导致读取失败。

| 原版版本 | 原版新增或变化 | 原生版读取行为 | 验证重点 |
|---|---|---|---|
| v1 | 核心 `animes`、`tags`、`anime_tags` 资料 | 读取存在的核心列；缺少的新字段使用安全默认值 | 标题、状态、数字评分、进度、标签 |
| v2 | `tv_episodes`、`sp_episodes` | 读取并将负数归零；旧库缺失时为 0 | TV/SP 集数 |
| v3 | `series` | 仅保留指向实际系列的 `series_id` | 系列与无效外键 |
| v4 | `watch_statuses` | 保留自定义状态；缺表时生成默认状态，并补入作品使用的自定义状态 | 状态颜色、顺序、作品状态 |
| v5 | `series.custom_cover_url` | 远程 URI 保留；ZIP 本地路径迁移并重写 | 系列封面 |
| v6 | `watch_records` | 仅导入指向现存作品的记录；负集数归零 | 打卡历史、孤立记录 |
| v7 | 原版无结构升级 SQL | 与 v6 相同，按实际表列读取 | 基础回归 |

| v9 | `reminder_day`、`reminder_time` | 字段保留，导入后统一重建提醒；无效值不会形成有效任务 | 每周提醒 |
| v10 | 默认状态乱码修复 | 映射已知历史乱码；空状态归为“未看” | 中文状态修复 |
| v11 | `anime_analysis_records` | 迁移服务端记录 ID、用户、模型、分析、统计 JSON 和时间 | AI 分析历史 |

| v14 | 角色 `rating`、`review` | 评分限制到 1–10，评价保留 | 角色个性化字段 |
| v15 | 角色表幂等补齐 | 按实际列读取，不依赖固定列顺序 | 角色关联回归 |
| v16 | 角色表幂等补齐 | 同 v15 | 角色组回归 |
| v17 | `character_groups.share_code` | 分享码、社区 ID、来源、公开状态一并迁移 | 社区角色组 |
| v18 | `animes.rating_grade` | 只接受 A/B/C/D；合法等级优先于同一行数字评分 | 等级评分 |
| v19 | `animes.fun_rating_tier` | 趣味评分层级原样迁移 | Tier List |

## 跨版本统一规则

- 必须存在 `animes` 表；否则文件不属于受支持的原版数据库。
- 缺失的可选表视为空集合，不会创建伪数据。
- SQLite 必须通过 `PRAGMA quick_check(1)`。
- 高于 v19 的库允许预检和尝试导入，但会警告未知字段被忽略；不承诺新表语义。
- 原版本地封面只有在 ZIP 含 `covers/` 时才能迁移。
- 原版 SharedPreferences 不属于数据库版本兼容范围。

## 关系与外键清理

- 作品标签、观看记录、作品角色、角色标签、角色组成员和角色组作品必须同时找到两端实体。
- 无效系列引用转为 `null`。
- 角色关系两端按较小/较大 ID 规范方向。
- 自关联和孤立关系不导入。
- 同一角色对只保留第一条有效关系，反向重复或不同关系类型的重复记录均剔除。
- 关系强度限制为 1–5。

## 当前验证证据

- 原版真实生成的两份 v19 启动样本：`PRAGMA user_version = 19`、16 张业务表、`quick_check = ok`。

- JVM 测试覆盖 v3 无效系列、v6 孤立关联及 v19 完整角色关系图。
- `test-fixtures/legacy_v19_full.zip` 覆盖 v19 完整业务表、封面和异常数据。
- Android 文件选择、SQLite 平台读取、恢复点和封面实际复制仍以真机手动用例为最终发布门槛。
