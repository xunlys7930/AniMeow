# 原版 v19 导入验证样本

运行：

```powershell
py -3 scripts/generate_legacy_v19_fixture.py
```

脚本以原版工程生成的空白 v19 数据库为结构基准，输出：

- `legacy_v19_full.db`：可直接选择的原版 SQLite 数据库。
- `legacy_v19_full.zip`：含 `anime_tracker_v5.db` 和 5 张本地封面的原版 ZIP 备份。

样本覆盖 3 部作品、1 个系列、2 个作品标签、观看记录、3 个角色、角色关系、角色标签、角色组、AI 分析历史、提醒和本地/远程封面。它还故意包含越界评分、负数进度、无效系列外键、反向重复关系、自关联、孤立关系和孤立关联表记录，用于确认导入时的规范化及清理行为。

预期重点：

- v19 与 `PRAGMA quick_check = ok`。
- 作品评分 `999` 导入为 `10.0`；负评分不生成数值评分。
- “看完”作品从 `2/8` 补齐为 `8/8`；负数集数归零。
- 角色评分限制为 1–10；关系强度限制为 1–5。
- 反向重复、自关联、孤立关系以及所有孤立关联记录被剔除。
- 5 张本地封面迁移到 AniMeow 私有目录，远程 HTTPS 封面保持原 URL。
- 导入前自动生成完整恢复点。
